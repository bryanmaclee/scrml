## Findings to fix (from an independent adversarial review at 42641506c — these are CLAIMS: reproduce each by execution BEFORE fixing; report whether each reproduced)
N1 (MEDIUM, would block U1): the re-run cap is bypassed once a run has suspended. `When.running` is false while a task is suspended, so a continuation that writes its own dep (through a call) or closes a cross-`when` cycle gets a fresh `run()` with `reruns = 0` each time → unbounded runs, microtask queue never drains, page hangs, 0 errors. Reviewer's runtime repro: `rt.when(s,[dep],(t)=>{runs++; rt.suspend(t,1,()=>bump())})` with `bump=()=>dep.set(dep.peek()+1)`, then `dep.set(1)` → 100,000 runs (stopped only by a guard). Cross-when variant: A(n) suspends then writes m; B(m) writes n. Without a suspension the same program correctly gives 2 runs + 1 error. Fix so the cap counts the whole causal chain including continuations — the suspended-continuation path must be bounded and reported exactly like the synchronous path. Keep ruling (b) intact (a genuine external re-trigger during suspension still cancels and starts fresh — do not let the fix turn newest-wins into a cap violation; design the distinction and explain it in DESIGN.md). Add runtime tests for both variants + a bite proof (revert the fix → red).

Governing: SPEC §6.7.4 "A `when` statement is associated with the enclosing element scope" (quote it from compiler/SPEC.md).
