## SPEC §14.8.10 — the subset's normative statement (read in full, quoted)

> **The SQL subset — anything else on a tenant table is refused (S452 r3).** A query that names a tenant-scoped table is legal without `.acrossTenants()` ONLY if it lies in an allow-listed SQL subset that the compiler reads exactly, token by token; a query outside it is **`E-TENANT-SQL-SUBSET`** … The subset:
> - **A closed token set.** Whitespace; unquoted identifiers `[A-Za-z_][A-Za-z0-9_]*` (qualified `a.b` is identifier `.` identifier); plain numbers (no hex, no digit separators); plain single-quoted string literals whose only escape is `''` (no backslash, no `${`, no control character inside); `${…}` interpolations, which are bound parameters and never SQL text; and the punctuation `( ) , . * = <> != < > <= >= + - / % ||`. ANY other character or form is outside: among others `"`, `` ` ``, `[`, `]`, `$` (other than `${`), `\`, `;`, `:`, `?`, `@`, `#`, `{`, `}`, a `--` or `/* */` comment, a prefixed literal (`E'…'`, `X'…'`, `N'…'`), and any non-ASCII character outside a literal. …
> - **One statement.** Exactly one statement, led by `SELECT`, `INSERT`, `UPDATE` or `DELETE` (`;` is not a token, so a second statement cannot exist).
> - **No escape from the floor's reading.** No `WITH`, no subquery …, no `IN <table>`, no `UNION` / `INTERSECT` / `EXCEPT`, no `OVER` / `WINDOW`, …
> - **Allow-listed functions.** Every function call is on the per-row allow-list (`lower` `upper` `length` `trim` `ltrim` `rtrim` `substr` `substring` `replace` `instr` `coalesce` `ifnull` `nullif` `abs` `round` `date` `time` `datetime` `julianday` `strftime` `cast`); a qualified callee (`schema.fn(…)`) never is. A read grouped by every tenant source's `tenant_id` may also call `count` `sum` `avg` `min` `max` `total`, and nothing else. …
> - **Detection does not trust a query it cannot read.** …
> The subset is an implementation's guarantee that what it scopes is what the database runs; it is deliberately small, and it MAY grow only by forms the implementation reads exactly.

## Design decisions (as built)

1. **Which part of the subset applies to a body.** The ruling names `lexTenantSubset`, the closed token set and the function allow-list. A body is held to: (a) the closed token set — the SAME lexer, unchanged except an opt-in `;` separator used ONLY for a trigger's `BEGIN … END` statement list; (b) the function allow-list — `TENANT_ROW_FUNCTIONS` ∪ `TENANT_GROUP_AGGREGATES` (+ SQLite `raise`) for view / trigger / rule / CTAS bodies, and the side-effect-free expression list for a policy's USING / WITH CHECK (unchanged from #1317 — `current_setting` is the §14.8.11 tenant pattern); (c) for a trigger, the subset's statement leaders: `BEGIN`, then `;`-separated SELECT / INSERT / UPDATE / DELETE, then `END`. NOT applied: the query grammar's "no subquery / WITH / UNION" — those rules exist so the floor can KEY a query's rows; a body is not keyed, it is refused when it names a tenant table at all (the existing hazard rules). Views over non-tenant tables legitimately join, aggregate and subquery.
2. **Call classification** stays `isSyntacticParen` (the closed syntactic set hardened by the #1313/#1317 rounds — stricter than the query subset's `NON_CALL_WORDS`), now over the subset's tokens (no quoted callee, no `[…]` subscript can exist there).
3. **Body extent.** The head (name, timing, `ON <table>`, a view's column list) is still read by the schema lexer (three comment readings); the BODY's raw text (`AS …` for a view, after `ON <table>` for a trigger / rule / policy, after `AS` for `CREATE TABLE … AS`) is sliced by token offsets and lexed by the subset. A comment, quote or `$$` inside a body is physically in the slice → refused in every reading.
4. **`rel.f` CLOSED — fail-closed qualified references.** Inside a body, `x.y` (not followed by `(`) is admitted only when `x` resolves, through the body's own bindings, to relations whose DECLARED columns all include `y`: FROM / JOIN / INTO / UPDATE / USING relations and their aliases, a trigger's / rule's NEW / OLD (its ON table), a policy's table, `excluded` (an upsert's INSERT target). Declared columns = `schemaColumnKnowledge` over every `<schema>` of the compilation: intersection of the SQLite (non-nesting) and Postgres (nesting) comment readings, intersection over a table's declarations, plus `ALTER … ADD COLUMN`, minus every renamed-away / dropped column; a view's columns = its explicit column list, else its first SELECT's readable item names. Refused: an unbound `x`, a CTE / derived-table alias (columns unknown; a CTE named like a table shadows it), a three-part reference, `(…).f`. A qualified name in a FROM position is a relation, not column access (guarded: `IS DISTINCT FROM`, and the token after must be one a FROM list allows). Expression regions (index / DEFAULT / GENERATED / CHECK / ALTER SET DEFAULT) get the narrow form: `own.f` must be a declared column of the statement's own table.
5. **Expression regions are NOT moved to the subset** (justified): Postgres column definitions are written with `::` casts (`DEFAULT '{}'::jsonb`, `'active'::text`, pg_dump's `nextval('s'::regclass)`), array types / literals (`text[]`, `ARRAY[]::text[]`, `= ANY (ARRAY['a'::text])`), and quoted columns (`CHECK ("order" > 0)`) — all outside the closed token set. They keep the #1317 expression-mode token allow-list (which models exactly those forms and holds every call / cast / operator / type to closed lists). Allow-list NOT extended. `now()`, `gen_random_uuid()`, `lower(email)` are already on the expression list.
6. **`CREATE TABLE … AS <query>`** — its query is a body the database runs at migration; read in the subset like a view's (was expression mode). Flagged for PA veto (adjacent to the ruling's four kinds).
7. **Kind / message.** New kind `body outside the tenant SQL subset`, unattributable (charged against every tenant table, the view tainted); the message names the declaration, the first offending token and its line.
