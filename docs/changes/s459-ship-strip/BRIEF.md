## Design constraints (load-bearing)
1. **ONE reader of the shipped text (S456/S457/S458 lesson — the two-readers-one-text bypass).** Several post-emit judges read EMITTED text: the §22.12 `^{}` executed-text checks, `validate-emit.ts` / emitted-call guards, the executable-sink / attr-injection checks, `__scrml_` placeholder emit gate, E-EVENT-UNBOUND on the final client text, `scripts/host-global-scan.ts` (CI), the SQL one-statement emitted-call guard. The strip MUST happen BEFORE every one of those judges reads the text, so the text judged is the text shipped — OR be proven token-stream-identical (acorn tokens before == after) at the point it runs and the proof fail CLOSED (on any mismatch ship the unstripped text and warn). Prefer: strip at the latest single assembly point AND assert token identity there. Enumerate every post-emit reader you find (file:function) and state for each whether it reads pre- or post-strip text.
2. **Behaviour-neutral by construction:** remove comments via acorn comment ranges (acorn is already a dependency) keeping a line break where a comment held one (ASI safety); whitespace via `Bun.Transpiler({ minifyWhitespace: true })` or an acorn-token reprint — no identifier renaming, no syntax rewrites (options 1c/2 are OUT). Keep any `sourceMappingURL`/`sourceURL`, `/*! */`, `@license`, `__PURE__` comments if present (measurement found none in the runtime; check client JS).
3. **Where it applies:** the shipped runtime file AND every emitted `.client.js` / per-route chunk / worker bundle shipped to the browser. NOT server.js (out of scope this round — report its comment share as a number only). The runtime chunk splitter (`runtime-chunks.ts`) finds boundaries via marker text inside comments → strip AFTER assembly/splitting, never before.
4. **Modes:** production = `scrml build` (all targets) strips by default. `scrml dev` keeps comments (readable). `scrml compile`: strip by default only when an explicit flag is set — make the documented-no-op `--minify` (`compiler/src/cli.js` ~:76) the switch for compile, and add `--keep-comments` for build (escape hatch). Decide and DOCUMENT the defaults in the CLI help + SPEC if any SPEC text claims emitted-JS shape (grep §47, §2, §58 for "readable"/"comment"); if a SPEC sentence normatively requires readable emitted JS, STOP and report it (ruling needed) — do not edit it.
5. Content hashes (§47 FNV, chunks.json) change for every stripped artifact — expected; confirm they are computed over the SHIPPED (stripped) bytes, never the pre-strip text.
