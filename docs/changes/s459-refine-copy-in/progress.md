## Governing-sentence gate (Rule 4) — before coding

- §53.3.3 (SPEC.md:40004): "The assignment is applied if and only if the predicate evaluates to `true`. If the predicate evaluates to `false` at runtime, the compiler-generated check SHALL throw a runtime error with code `E-CONTRACT-001-RT` before the assignment is applied. The variable retains its prior value." — copy-in makes "the variable" own exactly what was judged: a later write to some other reference cannot change what the cell holds without passing its check.
- §66.10 (SPEC.md:46007, Nominal/spec-ahead on impl#1, its own "impl#1 divergence (CARRIED)" note): "1. AXIOM: scrml has value semantics. A binding, argument or field initialized from a cell (or from any value) holds a snapshot of that value." · "2. No write to a source is observable through a value taken from it earlier; no write through such a value is observable in its source" · "5. (Non-normative.) … The copy strategy is not part of the contract." · item 6: instances and `as=` handles are identities, not values (not snapshotted). Copy-in of a refined cell is §66.10 applied to the cell side; identities (non-plain objects) are not copied.

## Design (as built — see later entries for deltas)

- ONE admission point per kind of write, each copies then judges the copy (copy first: a getter / proxy on the incoming value is read exactly once, so what is judged is what is stored):
  - whole write: the wrapped `_scrml_reactive_set` (every origin — handler, server result, `<request>`, channel sync, SSR seed, reset/default, bind:value, init — routes through it; the engine's two direct writes now store what the check returns).
  - in place: the cell's judging proxy (`set`, `deleteProperty`, `defineProperty`, `setPrototypeOf`, array mutators).
  - path writes `@a[i].f = v` (`_scrml_reactive_set(k, _scrml_deep_set(_scrml_reactive_get(k), path, v))` — every lowering is same-key): on a refined cell's current root the update is made IN PLACE through the judging proxies (the leaf is judged and copied by the `set` trap), and the trailing set is the cell's own value. Under `debounced=` / `throttled=` the copy-on-write path is kept (judged whole at schedule, copied + judged at commit).
- Ownership: one `place` per stored object — `{ key, d, parent }` (cell, descriptor of its position, containing object). Every stored object is a fresh copy, so it has exactly one place. An object is "in the cell" iff its parent chain reaches the cell's CURRENT root; an object removed in place (pop / shift / splice / shorter length / overwrite / delete) loses its place AFTER the operation succeeds. No counts, no epochs, no delta proofs.

  - Design decisions taken in the build:
    - copy FIRST, then judge the copy (a getter / exotic object is read exactly once: what is judged is what is stored).
    - a value reached twice is copied twice (a stored value is a tree — one place per object; preserving sharing would re-create the dup-at-two-positions class).
    - cyclic value → refused E-CONTRACT-001-RT (§45.1 values are acyclic); identities (non-plain objects, §66.10 item 6) held, not copied.
    - N4 model = TRAPS (not deep-freeze): freezing would make every in-place push / field write a copy-on-write of the whole value (O(n) per write — the MED-1 quadratic); traps keep writes O(1) and are the one place every in-place write already passes. defineProperty: data → copied + judged; accessor → refused; setPrototypeOf → refused; a `__proto__` key in an admitted value is data (defined, not assigned).
    - N1: every trap computes and judges first, applies through the deep-reactive proxy, and releases removed objects only after the operation returned (an invalid `length` reaches its RangeError before anything changes — ToNumber once).
    - path writes on the cell's own value are made IN PLACE (O(depth)); copy-on-write with structural sharing would need every off-path child re-parented (O(width) per write) or a deferred "this result is a path update" fact — the HIGH-1 stale-fact class. In place cannot go stale.
    - an UNREFINED cell can store a refined cell's value (`@draft = @ls` stores the same proxy — copy-in governs refined cells only). A path write through @draft must not land in @ls in place: the setter marks such a root (`_scrml_refine_shared_roots`, conservative, never cleared until the cell gets a new value) and path writes on it keep copy-on-write (whole copy + judge at the set). Writes through the shared proxy itself are still judged as @ls's.
    - a whole write KEEPS the cell's own direct children at the same position instead of re-copying them (`@ls = [...@ls, r]`, `@ls.filter(…)`): they are reachable only through this cell and the new value replaces the old. They are re-parented only after the new value is admitted; if anything moved one in between, the whole value is copied. (Spread-append 2000 structs: 2300–3170 ms without, ~800 ms with — r3 was 1150–1380.)
