## 2026-10-03 — built
- `scripts/bootstrap-conformance.ts`: pure bootstrap (no impl#1 stage). The codes half reuses run.ts's `loadCases` /
  `validateExpectContainers` and the same superset/disjoint/prefix/severity/count rules. The runtime half reuses
  driver.ts / fake-clock.ts / normalize.ts. Buckets: PASS · CODES-ONLY · FAIL · LEGACY · UNSUPPORTED (bootstrap-unsupported |
  parse-reject) · CRASH · INVALID. Annotations: VACUOUS (the only assertions are absences of codes no bootstrap source
  mentions) and "not in the bootstrap" on a FAIL (its required code is in no bootstrap source).
  A legacy-dialect case is never a FAIL. If the bootstrap accepts it silently and then answers wrong, it is LEGACY with
  `accepted-silently` and listed.
- Exit status is separate from the output: 0 = valid measurement; 1 only with `--fail-on-fail` / a stale `--check`; 2 = invalid run.
- Tests: `compiler/tests/integration/bootstrap-conformance-counter/` (8 fixtures, one per bucket, incl. a runtime-executed PASS
  and a runtime-half FAIL; two bites: misspelled expected code → FAIL, a forbidden code that fires → FAIL; CLI exit codes). 18/18 pass.
- Report: `docs/bootstrap-conformance.md` (generated by `--write`; deterministic, two runs diff-identical). Not a FACTS row:
  FACTS excludes run-derived figures by its own rule.
- CI: one NON-BLOCKING step in the `tracking` job (`--check`, step-level continue-on-error, ~7 s). Not in `gate`.
