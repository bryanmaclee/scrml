## Governing-sentence gate

SPEC §38.6.1 (`onserver:message` Parameter Binding), normative:
- "The compiler SHALL parse the call expression in `onserver:message=<call>` as `<handlerName>(<paramName>)`."
- "The compiler SHALL emit an error (E-CHANNEL-005) if `onserver:message` contains more than one parameter in the call expression."
- (rationale) "the identifier in the call expression names the value the compiler will inject, not a variable already in scope."

SPEC §38.9 / §34 row: `E-CHANNEL-005 | §38.9 | onserver:message call expression contains more than one parameter | Error`.

SPEC §38.10.1 / §38.10.2 (`onclient:*`):
- "The attribute value is a function call expression. The parameter binding follows the same event-injection pattern as §5.2.2"
- "If the call expression contains no parameter (e.g., `onclient:open=handleOpen()`), the event object is not passed to the handler."
- "The compiler SHALL bind the parameter name in the call expression to the event object using the same injection mechanism as `onclick=handler(e)` (§5.2.2)."
- SILENT on: a second argument; a first-argument name that collides with an in-scope declaration.

The brief's "handler attribute params are function-local locals" rule: NOT FOUND in §38 (grep). The nearest text is the
§38.6.1 sentence quoted above ("names the value the compiler will inject, not a variable already in scope").

## Locus finding (premise correction)

E-CHANNEL-005 is NOT implemented anywhere. `grep -rn E-CHANNEL-005 compiler/src` → one hit, a COMMENT
(`symbol-table.ts:9499` "Channel attribute shape errors (E-CHANNEL-001/E-CHANNEL-005/E-CHANNEL-007 — codegen-time today)").
Empirical: `onserver:message=handleMessage(msg, extra)` compiles exit 0 and the server emits
`await handleMessage(msg, extra);` with `extra` a free (undefined) identifier → ReferenceError at runtime.
`onclient:open=onOpen(x, 1)` with `<x> = 5` compiles exit 0 → `_ws.onopen = (x) => { _scrml_onOpen_2(x, 1); };`.
