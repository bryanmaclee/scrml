## Key Facts

- Entry point: `compiler/bin/scrml.js` -> `compiler/src/cli.js` dispatches to `commands/*.js` (11 subcommands); the pipeline is `compileScrml()` in `compiler/src/api.js` (block-split -> AST-build -> type-check -> codegen).
- **THE MAP-STAMP DEFECT IS FIXED AT THE SOURCE THIS PASS, AND THE DIAGNOSIS IS THE TRANSFERABLE PART.** Invariant 48 has said "verify the stamp is an ancestor" since S326, and the defect recurred THREE more times. It recurred because **the row specified the INBOUND check and the failure is on the OUTBOUND side** — the S331 author ran `--is-ancestor <old-stamp> HEAD`, watched it pass, wrote the correct outbound SHA into the very next sentence of the header, and then stamped the branch tip anyway. **A rule that names the command but not the MOMENT does not bind.** The procedure is now at the top of this file. Measured on arrival: 3 of 5 distinct live stamps were orphaned branch tips, one of them (`fe14c9b2`, schema.map.md) for ~ten sessions.
- **A SILENT INSTRUMENT IS WORSE THAN A RED ONE, AND THIS IS THE WORKED EXAMPLE.** `scripts/state.ts:545` correctly REFUSES to compute a behind-count from a non-ancestor watermark — it will not print a wrong number. But the refusal terminates there: the pre-dispatch maps-currency check `pa-scrml-overlay.md {{maps_fills}}` mandates before EVERY dev dispatch simply returned nothing, and nothing escalated. **A mandatory step was unanswerable for three of the last six map generations and no gate noticed.** Verified fixed at this pass: the probe now prints a real behind-count.
- **A COLLECTOR THAT ENUMERATES AST FIELD NAMES IS FAIL-OPEN (invariant 52).** `collectDerivedCellDecls` descended `body` and `children` while claiming "at any depth"; six positions leaked `Bun.password.hash` into the browser bundle at exit 0. **The fix inverted the default** — descend everything, deny-list the exceptions — and the deny-list was then measured NOT load-bearing for the result (68 cells with it, 68 without it entirely). **Never close a miss in this class by adding the field name.** This is the compiler's second instance of the class.
- **THE §34 CATALOG MOVED FOR A SECOND CONSECUTIVE WINDOW: 807 -> 809.** `E-EACH-BODY-DECL-UNSUPPORTED` (§17.7.3) and `I-SSR-EACH-CLIENT-RENDERED` (§52.8). Both were PINNED by a conformance case in the same PR that emitted them — PINNED moved 341 -> 343 in lockstep, and each `expected.json` was READ to confirm a real `expect.codes` assertion rather than a rationale-prose mention.
- **A COUNT THAT WALKS THE FILESYSTEM IS NOT A REPO FACT.** The prior map published `1887 source files` from `s34-census.ts`; it does not reproduce at any commit, because `filesScanned` walks ten directory roots on disk and therefore counts whatever gitignored build output the checkout happens to hold. Tracked truth: **1,850 -> 1,858 (+8)**. Same shape, different direction, in FACTS.md: `test files` counts only `*.test.js` (**1,339**) and excludes 15 `*.test.ts`, so a `git ls-files '*.test.*'` returning 1,361 is not a contradiction. **State which derivation produced a number.**
- **TWO OF THE THREE NEW `scripts/` FILES EXIST BECAUSE AN OBLIGATION WAS RECORDED IN ONE ARTIFACT WHILE EVERY PROBE READ ANOTHER.** `dpa-debt.ts` was written after `dpa-024` sat `BANKED — UNRUN` for six sessions: the boot gate probed review-debt, the thread board, gh issues/PRs and CI — every inbound channel except the deliberation queue. **The rule it discharges: a channel the probe does not read does not exist to the PA.** It is also deliberately BIDIRECTIONAL — it reads the authoritative status TABLE *and* re-parses the per-item `status:` lines and reports disagreement, because the failure it was written for was a STALE TABLE, and a probe that trusts its authoritative surface unconditionally cannot see that surface go wrong.
- **A REGEX OVER SOURCE TEXT IN A POST-AST STAGE NEEDS A JUSTIFICATION OR THE STRUCTURAL ROUTE (invariant 55).** Five instances, five authors, one session, two unrelated branches — **and none was caught by a 22,385-test suite or a 7,375-artifact differential**, because the class is invisible to differentials by construction. Detection is a RATIO (`source-text-regex-census.ts`), deliberately not a CI gate.
- **THREE PRs TO CLOSE ONE ATTRIBUTE-ROUTING CLASS, BECAUSE EACH PATH ARRIVES AS A DIFFERENT NODE SHAPE (invariant 54).** The `<each>` body attr needed a threaded `requestIds`; the `${for…lift}` attr needed a REPARSE first, because `shouldSkipExprParse` skips any `<`-leading expr so no structured node exists to thread into. **Every fix is gated on REGISTERED request ids**, which is what let the class close incrementally with a byte-identical corpus.
